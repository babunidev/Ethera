## Reconciled decisions

| Topic | Current rule | Earlier material replaced or limited |
| --- | --- | --- |
| Tasks | Suggested order; actual fulfilled condition completes the task, including help from another player. | Mandatory checklist route or required personal acquisition of every intermediate step. |
| History | Separate latest-100 interaction log; discard completed task objects. | Indefinite personal interaction history or retained completed-task database. |
| Names | Inner Harmony, Elemental Sustenance, Living Stone Adornment and Echo Attunement are selected in-world names. | Provisional function labels and open-name questions. |
| Shards | Unique immutable factual event records shared by stable reference. | Generic reusable knowledge flags as the entire Shard model; editing an old record into a newer report. |
| Round | One primary action, any reactions and final result produce one event Shard. | Separate reaction Shards or several newly generated event Shards for one round. |
| Failure | Failed player-skill attempt creates no Shard. A prevented effect still records the successful resolved action. | The related prototype's suggestion to record failed attacks as Shards. |
| Result fields | One or several stable result references; several actors/targets/reactions, one action and place. | Earlier single-result-only and possible multiple-action sketches. |
| Echo Attunement | Up to one unknown Shard per direction, prioritized then needed then random. | Automatic wholesale copying or manual browsing of another person's knowledge. |
| Retention | Ordinary one-world-week lifetime from original creation; authored Fountain permanence and archival preservation. | Unlimited automatic communal history or refresh on transfer. |
| Archival stones | Three filled-once slots; preserve any chosen known Shard; multiple stones can preserve the same ID. | Unlimited or overwritable archival storage. |
| Stone destruction | Only Memory Binding consumes memory/archival stones after transfer. | Earlier destruction/loss examples as general gameplay destruction rules. |
| Item use | Relevant Trait or knowledge required. | Unconditional usability of unfamiliar items. |
| Physical initiation | World target initiates; UI choices occur within that interaction. | Inventory-only archival activation or separate socket/remove actions. |
| Combat targeting | Random valid part by default; Aimed Attacks enables choice. Defensive choice requires a relevant Trait. | Unrestricted body-part choice. |
| Injury/defense | Binary injury; defense prevents it in the reaction phase. | Severity tiers, partial reduction, redirection and added Mountain Strike stun/knockout outcomes. |
| Attack checks | Eligibility before wheel display; player skill determines execution success. | Extra capability rolls, size/material modifiers or defense blocking eligibility. |

## Source precedence and remaining ambiguity

The user's direct corrections in Interactions govern its assistant-written prototype. The main discussion's explicit failure and one-Shard-per-round decisions govern conflicting prototype prose. The user's supplied twelve-name table governs earlier uncertain naming. That taxonomy is retained as a proposal, without imposing a new hierarchy.
