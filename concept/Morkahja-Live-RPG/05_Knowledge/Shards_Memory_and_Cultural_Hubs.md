# Shards, Memory and Cultural Hubs

A Shard is an immutable factual record of a resolved interaction round or a discovery event. It identifies the people or objects involved, the action, any reaction, the final result, the place and the exact world time. Knowledge gives characters access to these records and lets their experiences become useful to others.

## Events become knowledge

After a successful player-skill phase, any reaction resolves and the world applies the final result. The round then creates exactly one event Shard. A successful strike whose injury is prevented still produces a record of that resolved exchange. A failed player-skill phase produces no Shard.

Two strikes are two different historical events, each with its own stable Shard ID. A later healing interaction creates a new record alongside the injury record. Practical understanding draws on what those events establish: a particular creature was at a place, a person performed a healing action, or a maker created an object.

For example, Buxor strikes a particular bear's left foreclaw at Northern Ridge. The Shard records that exact actor, bear, Mountain Strike, reaction, injury result, place and time. A subsequent encounter can establish where that bear moved or how its condition changed.

## Shared access

Characters, the Memory Fountain, memory stones, monuments, ruins and other suitable entities can be Shard-holders. Each holder knows a set of Shard IDs. Learning a Shard grants a reference to the existing record; the source keeps its reference. Knowing the same Shard again leaves the holder's knowledge unchanged.

Shards occupy the knowledge system. Physical stones are objects that hold references to them. Ordinary knowledge collection has no numerical capacity burden; retention determines how long a holder remembers each record.

## Fountain knowledge

**Echo Imprint** automatically contributes one known Shard the Fountain lacks. **Echo Attunement** automatically retrieves one needed Shard available in the Fountain. Each use grants a reference to the existing record while its source keeps access. Successful uses create an additional event Shard recording the learned reference.

Imprint checks the character's known IDs against the Fountain; Attunement checks needed IDs. The [complete interaction rules](Echo_Imprint_and_Attunement.md) define requirements, selection and availability.

## Pickup

Every pickup writes an event Shard. **Only the picker** receives it. A later pickup of the **same item** discards that holder's previous pickup Shard for that item and keeps the new one. Taking an item from an opened container is a pickup. Ordinary loot can become a quest objective; there is no separate shardless loot class.

Opening an unlocked container writes a **discovery** Shard — who found it, where it is — known only by the opener. Shaping a rock into a weapon is not a discovery; it already has its own event Shard.

The Fountain never learns these records by itself. It learns only through Echo Imprint.

## Discovery

Hovering an on-screen interactable world object can create a discovery Shard automatically. A stone circle record identifies the discovering character, the exact landmark, Action Discovery, Reaction None, Result Discovered, its place and world time. The character can contribute it through Echo Imprint. This observation uses the same record structure and knowledge references as an authored interaction result.

## Living memory and preserved history

Ordinary holders retain a Shard for one week of world time measured from its original creation. A three-day-old Shard learned today has four days of ordinary retention remaining. Exchange, rereading and transfer preserve that original time.

The Memory Fountain retains authored permanent Shards indefinitely once it learns them. Its ordinary Shards follow the same one-week rule. Archival stones can preserve any deposited Shard indefinitely. These holders allow selected knowledge to outlive its discoverer.

When a character dies permanently, their knowledge references are removed. A record can be deleted when no character, Fountain, object, task or other system references it. Knowledge lost from every holder must be rediscovered through new events.

Historical facts remain true of their own moment. A newer report changes the useful lead while older records remain unchanged for as long as their holders retain them.

## Cultural sources

| People | Knowledge tradition |
| --- | --- |
| Grimnir | Memory Fountain, memory and archival stones, resonance, architectural records and Memory-Keepers; later Skykeepers carry records between communities. |
| Verdani | Memory Pools and Memorykeepers preserve experiences in enchanted water. |
| Rokur | Clan-Hearths, Hearthkeepers and storytellers carry reports and history through oral teaching. |
| Aevis | Crystal archives, harmonic chambers and Resonance Archives support communal knowledge. |

Grimnir resonance stones carry stories through wind, voice and attunement. Ancestral impressions give cultural form to experience, emotion and craft; Memory-Keepers help visitors interpret those patterns. Deliberate preservation supports archives spanning generations.

## Tasks and changing leads

Consultation at the Memory Fountain can still supply unknown information for common-area Needs. It does not replace Divine Orientation for a selected objective that still exists. If a quest object was destroyed, a replacement is placed into unused world-node content. Learned information can still support a destination; orientation toward a living objective uses the object's current place, not a location Shard.

The Fountain does not invent knowledge. It stores and redistributes Shards that have genuinely entered the knowledge system. The task system must not create a Shard merely to make a Need easier. If neither the character nor the Fountain holds useful knowledge, Divine Orientation can still hold an angle toward the reserved objective.

A healing Need can lead to a staff and a capable healer, or suitable knowledge can let the person treat themselves. An already-equipped healer can directly resolve the injury. Task completion follows the achieved condition.

A traveler seeking a bear claw may learn that the bear was killed and someone carried the claw home. Their next lead becomes that holder. Makers, ownership changes, communal stores and returned scouts provide other chains of useful facts.
